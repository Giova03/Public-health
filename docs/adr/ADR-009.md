# ADR-009 — Authentification : Supabase Auth d'abord, Keycloak en réserve

- **Statut** : ACCEPTÉ (arbitrage du porteur, phases 3–4)
- **Date** : 2026-09

## Contexte

Besoin d'une authentification solide (MFA administrateur) sans exploiter un serveur d'identité au Sprint 0.

## Décision

Supabase Auth pour l'authentification (JWT vérifiés côté API, plan 2 de la défense en profondeur), RBAC × ABAC applicatif. Keycloak reste la cible de migration institutionnelle : les rôles et habilitations sont modélisés neutres (module identity).

## Conséquences

Démarrage immédiat, migration documentée. Le verrouillage est faible : les JWT restent standard.
