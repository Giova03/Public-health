# ADR-001 — Monolithe modulaire à 15 modules

- **Statut** : ACCEPTÉ (arbitrage du porteur, phases 3–4)
- **Date** : 2026-09

## Contexte

Le mandat suggérait des micro-services ; l'équipe de démarrage est réduite, le budget contraint, le risque opérationnel élevé. La distribution précoce tue plus de projets qu'elle n'en sauve.

## Décision

Un seul déploiement, 15 modules (patient, identity, organization, appointment, encounter, consultation, prescription, pharmacy, payments, notification, audit, administration, sync, fhir, hub). Chaque module suit le style hexagonal (domaine / application / adaptateurs) et cinq lois de fer : un module = un schéma PostgreSQL ; communication inter-modules par interfaces ou événements uniquement ; aucune clé étrangère ni JOIN inter-schémas ; seuls fhir et hub parlent « étranger » ; les DTO d'adaptateurs sont des contrats stables. Les critères d'extraction future sont documentés.

## Conséquences

Dépendances inter-modules quasi nulles, testabilité haute, extraction micro-service possible plus tard sans réécriture. Contrepartie : discipline permanente (revue de code + tests d'architecture à venir en E5).
