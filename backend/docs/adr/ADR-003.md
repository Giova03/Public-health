# ADR-003 — PostgreSQL unique, un schéma par module, Flyway seul maître

- **Statut** : ACCEPTÉ (arbitrage du porteur, phases 3–4)
- **Date** : 2026-09

## Contexte

Besoin d'une base relationnelle solide, d'un historique de schéma auditable, et d'isolation logique par module sans multiplier les bases.

## Décision

Une seule base PostgreSQL (Supabase en hébergement géré, région UE — Francfort). Chaque module possède son schéma. Toute évolution passe par des migrations Flyway versionnées (V1 → V5 livrées) ; Hibernate ne crée ni ne modifie jamais rien (ddl-auto: none).

## Conséquences

Historique lisible, rollback maîtrisé, RLS possible par schéma. Le verrouillage fournisseur reste faible (SQL standard + Docker pour l'auto-hébergement, décision D4).
