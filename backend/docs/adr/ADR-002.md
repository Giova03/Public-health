# ADR-002 — FHIR R4 en façade, jamais en stockage

- **Statut** : ACCEPTÉ (arbitrage du porteur, phases 3–4)
- **Date** : 2026-09

## Contexte

Le PH HUB et les partenaires parlent FHIR R4. Mapper FHIR directement en base (tables par ressource) produirait un modèle anémique et gelé, inutilisable pour le métier.

## Décision

FHIR R4 (~19 ressources) est un CONTRAT d'interopérabilité exposé par le module fhir uniquement. Les domaines gardent leurs modèles souverains ; la traduction se fait aux frontières. Le validateur HAPI est branché dans la CI dès Sprint 0.

## Conséquences

Interopérabilité sans sacrifier le modèle métier. Coût : doubles définitions à maintenir et vigilance sur la dérive des profils — d'où la validation systématique.
